## 2024-05-24 - [CRITICAL] Information Disclosure in API Exception Handler
**Vulnerability:** The API endpoint `/check` returned full exception details (`detail=str(e)`) to unauthenticated clients on internal server errors, leaking sensitive stack traces and potentially underlying implementation details. Also identified unbounded Pydantic string inputs leading to potential DoS, and overly permissive CORS setup (`allow_origins=["*"]`).
**Learning:** Returning `str(e)` directly in HTTP responses is a critical anti-pattern in FastAPI that exposes internal application state. FastAPI endpoints must always decouple internal logging from client-facing error messages.
**Prevention:** Always log exceptions internally using `logging.error(e, exc_info=True)` and return generic, non-sensitive error messages to clients (e.g., "Internal Server Error"). Use Pydantic's `Field(..., max_length=X)` to bound all incoming strings, and explicitly map CORS `allow_origins` to trusted frontend URLs via environment variables.
