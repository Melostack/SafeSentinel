## 2024-06-25 - [API Security Improvements]
**Vulnerability:** Found multiple vulnerabilities in `api/server.py`: Overly permissive CORS configuration (`allow_origins=["*"]`), missing input validation on Pydantic models (allowing unbounded string inputs and DoS risk), and information leakage in the global exception handler (returning `str(e)` which could expose stack traces or internal implementation details).
**Learning:** These vulnerabilities often appear together in rapidly developed FastAPI applications. `["*"]` in CORS allows any domain to request data, which is especially dangerous if combined with credentials. Lack of input limits allows attackers to exhaust server memory or CPU by sending excessively long strings. Exposing exceptions directly to users can reveal database structure, API keys used internally, or other sensitive data.
**Prevention:** Always restrict CORS to known domains using environment variables. Always define `max_length` for string fields in Pydantic models (e.g., `Field(..., max_length=100)`). Always log exceptions internally using `exc_info=True` and return generic error messages (e.g., "An internal error occurred") to the user.
