## 2024-04-07 - [CRITICAL] Stack Trace Leak in 500 Responses
**Vulnerability:** The `/check` endpoint in `api/server.py` leaked raw exception strings directly to users via `detail=str(e)` inside the 500 Internal Server Error response. This type of information disclosure exposes internal application state and architecture details to potential attackers. Additionally, the FastAPI app utilized an overly permissive CORS setup (`allow_origins=["*"]`), allowing unauthorized domains to interact with the API.
**Learning:** Returning `str(e)` in an API response is a critical security anti-pattern because it often contains stack traces or internal variable states. Moreover, `allow_origins=["*"]` defeats the purpose of CORS. Adding authentication to public APIs is a significant architectural decision that must be weighed carefully to avoid breaking client applications like frontends that cannot securely store static API keys.
**Prevention:** Exception handlers must log the full exception internally (using `logger.error(..., exc_info=True)`) and return only generic, safe error messages to clients (e.g., "Internal server error occurred"). CORS must be explicitly restricted to expected origins (e.g., using `os.getenv("FRONTEND_URL")`).
