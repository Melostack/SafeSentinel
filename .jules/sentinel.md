## 2024-04-16 - [HIGH] Fix CORS Vulnerability and Error Leakage
**Vulnerability:** The API server had two high-priority security issues. 1) The CORS middleware was configured to allow all origins (`allow_origins=["*"]`), opening the API to cross-origin attacks. 2) The `/check` endpoint's exception handler returned raw exception strings (`str(e)`) to the client, potentially leaking sensitive internal system information or stack traces.
**Learning:** These vulnerabilities often arise during rapid prototyping or debugging when developers prioritize functionality over security. The `allow_origins=["*"]` pattern is common but dangerous in production. Leaking raw exceptions is a frequent oversight in FastAPI exception handling.
**Prevention:** 1) Restrict CORS origins strictly to trusted domains (e.g., using a `FRONTEND_URL` environment variable) and ensure it fails closed if the variable is not set. 2) Never return raw exception strings in API responses. Instead, log the full error with stack traces (`exc_info=True`) internally and return a generic, safe error message to the client.
