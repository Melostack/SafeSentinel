## 2024-05-23 - [HIGH] Fix overly permissive CORS and information leakage
**Vulnerability:** The API server had `allow_origins=["*"]` configured in its CORSMiddleware, which is a HIGH priority vulnerability as it allows any origin to make requests to the API. In addition, the `/check` endpoint returned raw exception stack traces/details to the client via `detail=str(e)` inside an `HTTPException`, which is a MEDIUM priority information leakage vulnerability.
**Learning:** Overly permissive CORS and returning raw error messages can lead to security bypasses and information leakage that an attacker could use to find further vulnerabilities. The use of `allow_origins=["*"]` should be strictly avoided for sensitive APIs, and exception handlers should always log errors internally and return safe, generic error messages to clients.
**Prevention:** Always restrict CORS origins using environment variables (e.g., `os.getenv("FRONTEND_URL")`). Always log exception details internally using `logging.error(e, exc_info=True)` and return a generic error message (like "Internal server error") to the client.
