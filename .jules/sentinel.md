## 2024-05-18 - Overly Permissive CORS, Missing Pydantic Limits, and Exception Leakage
**Vulnerability:** `api/server.py` had three security issues: 1) CORS `allow_origins=["*"]` allowed any site to access the API. 2) Pydantic models `CheckRequest` and `IntentRequest` had no string length limits, exposing the API to DoS attacks. 3) The unhandled exception in `/check` returned `str(e)` directly to the client, leaking internal details.
**Learning:** These three issues frequently appear in FastAPI applications built without restrictive defaults. Pydantic strings are unbounded by default, CORS middleware examples often use `*` for convenience, and `detail=str(e)` is an anti-pattern that exposes system internals.
**Prevention:** 1) Always tie CORS `allow_origins` to a controlled environment variable (e.g., `FRONTEND_URL`). 2) Use Pydantic's `Field(..., max_length=X)` for string inputs. 3) Catch unhandled exceptions, log them with `logger.error(..., exc_info=True)`, and return a generic error message (e.g., `"Erro interno do servidor"`).
