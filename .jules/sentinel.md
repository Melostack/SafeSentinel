## 2024-05-18 - [Fix] Prevent Information Leakage and Unbounded Inputs in FastAPI
**Vulnerability:** The FastAPI endpoints `/check` and `/extract` exposed internal stack traces and error details to end-users via `raise HTTPException(status_code=500, detail=str(e))`. Additionally, Pydantic models `CheckRequest` and `IntentRequest` used unbounded strings, posing a Denial of Service (DoS) risk through excessively large payload attacks.
**Learning:** Returning `str(e)` directly in an API exception handler can inadvertently leak sensitive system information, configuration details, or stack traces which can be leveraged by attackers. Failing to bound string inputs in web framework validation models opens up the risk of simple application-level resource exhaustion.
**Prevention:** Always catch broad exceptions (`except Exception as e`), log the full error stack trace internally using `logger.error("Message", exc_info=True)`, and return a generic, static message like `"Internal Server Error"` to the client. Apply `Field(..., max_length=N)` for all string inputs in Pydantic models to strictly enforce payload size limits.
