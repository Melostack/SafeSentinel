## 2025-07-29 - [Fix Parameter Injection in Connectors]
**Vulnerability:** The `BinanceConnector` built HMAC query string signatures using manual string concatenation `query_string = '&'.join([f"{k}={v}" for k, v in params.items()])`, which is vulnerable to parameter injection if parameter values contain `&` or `=`.
**Learning:** Manual construction of query strings for cryptographic signatures is a recurring antipattern in this codebase's connector implementations. This extends to `BybitConnector` which also used string concatenation. Additionally, `BybitConnector` had a subtle flaw where the signature and headers could use slightly different timestamps due to two separate calls to `time.time()`, potentially causing random auth errors. Furthermore, modifying signature function signatures (e.g., adding `timestamp` to `BybitConnector._generate_signature`) without default values risks breaking other methods in the class.
**Prevention:** Always use standard library functions like `urllib.parse.urlencode` to construct URL query strings safely, especially when they are used as inputs for HMAC signatures. Ensure API authentication headers and signatures derived from timestamps share the exact same timestamp string variable to prevent race conditions. Ensure any new parameters added to internal helper methods like `_generate_signature` have default values (`timestamp=None`) to preserve backwards compatibility.
