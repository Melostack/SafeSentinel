## 2024-04-26 - Information Leakage & Parameter Injection
**Vulnerability:** The API endpoints (`/check`) leaked raw exception messages (including possible stack details depending on exception type) via HTTP 500 responses. Also, the Binance and Bybit API connectors constructed query strings via manual string concatenation and f-strings, exposing the app to parameter injection vulnerabilities.
**Learning:** Returning `str(e)` directly to the client exposes internal workings and potential sensitive context if an unexpected exception occurs. Manual concatenation of query strings without encoding enables injection of extra parameters (e.g., overriding settings) if the input isn't strictly controlled.
**Prevention:** Always use `logging.error(e, exc_info=True)` for internal logging of unhandled exceptions, and return a generic safe message (e.g., "Internal server error") to the client. Always use URL-encoding utilities like `urllib.parse.urlencode` to securely construct query strings for API requests.
