## 2024-05-30 - Unauthenticated Access and Information Leakage on API Endpoints
**Vulnerability:** Core API endpoints (`/check`, `/extract`) orchestrating paid/rate-limited external services (e.g., OpenRouter AI, Blockchain RPCs) lacked authentication, making the system vulnerable to unauthorized API quota depletion and DoS attacks. Additionally, error handlers were leaking raw exception details (`str(e)`) to the client.
**Learning:** Internal APIs that consume external quotas must be protected by default. Relying solely on CORS or obscurity is insufficient. Furthermore, exposing raw stack traces or error strings can aid attackers in reconnaissance and must be avoided.
**Prevention:** Always implement an API Gateway pattern or direct header authentication (like `APIKeyHeader` in FastAPI) for sensitive endpoints. Ensure that global exception handlers log the raw error securely and return a generic, non-sensitive error message to the client. Validate secrets using constant-time comparison (e.g., `secrets.compare_digest`) to prevent timing attacks.
