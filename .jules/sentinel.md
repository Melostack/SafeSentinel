## 2024-05-30 - [API Hardening: CORS, Pydantic Limits, and Error Masking]
**Vulnerability:** The FastAPI server used `allow_origins=["*"]`, allowed unbounded request bodies in Pydantic models (DoS risk), and leaked internal error stack strings to unauthenticated clients in the `/check` endpoint.
**Learning:** These represent a trifecta of missing secure defaults in new backend configurations. Developers often use `*` for CORS during rapid prototyping and rely on raw Python exceptions, inadvertently creating security risks as the app moves toward production. Pydantic constraints (`max_length`) are crucial and often omitted.
**Prevention:** 1) Always configure `CORSMiddleware` using domain whitelists driven by environment variables (`FRONTEND_URL`). 2) Use Pydantic's `Field(..., max_length=X)` for all incoming string data to bound memory allocation. 3) Standardize exception handling at the API edge to strictly log exceptions internally (via `logging.error(e, exc_info=True)`) and present a generic sanitized HTTP response to the caller.
