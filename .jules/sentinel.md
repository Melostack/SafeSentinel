## 2024-05-25 - Information Leakage & DoS via API Endpoints
**Vulnerability:** The API server had multiple security gaps: 1. Overly permissive CORS (`allow_origins=["*"]`). 2. Unbounded Pydantic string fields allowing arbitrary length input (DoS risk). 3. Raw exception strings returned to users on failure (`detail=str(e)`), leaking internal details.
**Learning:** Default configurations in frameworks (like permissive CORS or unconstrained input models) create significant security debt. It's critical to limit allowed origins, strict parameter limits, and generic exception handling to prevent reconnaissance.
**Prevention:** 1. Use environment variables (like `FRONTEND_URL`) to dynamically set CORS origins, defaulting to localhost. 2. Always use `pydantic.Field` with a `max_length` attribute for text input. 3. Ensure generic error responses like "Internal Server Error" are returned while specific exceptions with stack traces are logged using `logging.error(e, exc_info=True)`.
